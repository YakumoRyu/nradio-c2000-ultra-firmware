# 维护与发布

## 版本

完整固件标签为`ultra-25.12-YYYYMMDD-rN`。维护升级包单独使用`ultra-maintenance-YYYYMMDD-N`标签。修订产生新标签，已发布产物保留追溯记录。

## 迭代流程

1. 记录问题、受影响版本、复现步骤和预期行为。
2. 检查现状并备份，形成最小修改与回退入口。
3. 按变更范围回归。AT/SMS检查唯一串口持有者、应答/主动上报和短信读/投递状态；网口检查配置事务、确认回退和现有链路。
4. 以真实浏览器和业务请求验收，记录CPU、内存、接口错误及流量。
5. 更新CHANGELOG、软件包版本、构建输入与验证记录，完成隐私检查。
6. 分别发布维护升级包和完整固件。完整镜像在硬件启动验收前标记预发布；启动验收通过后更新状态。

## 后续验收

- 完整r4镜像的实机启动与布局升级。
- 真实新短信到达时，Web查看与PushPlus接收同时正常。
- 发送/删除短信、扫频和锁频的实机流程。
- 有线上级设备实际DHCP/PPPoE接入。
- 大型二进制输入与完整构建流程持续整理。

生产路由器按明确任务进行安装、重启和刷写。项目记忆见[PROJECT_MEMORY.md](PROJECT_MEMORY.md)。

# 维护与发布流程

## 版本规则

固件使用 `ultra-25.12-YYYYMMDD-rN` 标签。软件包使用自身版本，例如 WebUI `3.0.2-r2`。同一标签对应的固件不得原地替换；修订后发布新的 rN，旧版保留追溯记录。

## 每次迭代

1. 在 Issue 中记录可复现的问题、受影响版本与预期行为，日志先脱敏。
2. 新建修复分支，记录上游变动或本地补丁；避免直接滚动更新所有依赖。
3. 对实际修改范围执行回归。AT/SMS 改动需检查串口唯一持有者、命令应答与主动上报、短信数据库及转发状态。
4. 更新 CHANGELOG、固定源码提交、包版本和验证记录。不得把单项 HTTP 200 或服务 running 状态当作用户流程验收。
5. 固件作为 Release 附件上传。整镜像尚未实机启动的构建标记为 prerelease，并明确尚未验证项目。
6. 实机启动后验证 IPv4/IPv6、Wi-Fi、5G、UPnP、媒体与资源限制，再判断是否转为稳定发布。
